```text
- when logs are sent to files - add [time]
- when logs are sent to docker - skip [time]
- sender is a string uniquely identifies sender in entire codebase; think of it
  as of javascript const within single namespace/block
- group_uid - a unique string (usually generated by cuid); used to keep logs
  from the same logical group together;
- group_spawn and group_exit are keywords
    - group_spawn is declare new group_uid and its parent (if any)
    - group_exit is optional and mainly used to detect leaks
- _begin, _end, _end_ok, _end_error - are established suffixes to denote start
  and end of a function/block
```



# Logs

One physical line records one event:

```
[time][group_uid][sender] details
```

A line carries these three fields and nothing else. Elapsed time, status, and
every other measurement belongs in `details`.

When the program owns the timestamp:

```
[2026-08-17T16:09:20.185Z][cd8e5vqp][db_query_begin] name=select_users
```

When a runtime or collector adds the timestamp as metadata:

```
[cd8e5vqp][db_query_begin] name=select_users
```

## Fields

### time

- ISO-8601 UTC with milliseconds: `2026-08-17T16:09:20.185Z`.
- Required when writing directly to a file.
- Omitted when the runtime already timestamps the line, as docker does.

### group_uid

A group is one unit of work, such as a request, job, or cron run. Every event
carries its group's uid. The uid is opaque, usually a cuid.

The first event of a group is `group_spawn`:

```
[new_group_uid][group_spawn] parent=old_group_uid
```

Omit `parent=` for a root group. Emit `group_spawn` synchronously before
passing the uid to other work or emitting another event for the group. Messages
and requests carry the caller's uid; the receiver uses it as the parent of its
new group.

### sender

- Identifies one logging call site.
- The name is unique in the whole codebase, so a grep for it lands on one
  place. Think of it as a `const` in a single namespace.
- Uses snake_case and matches `^[a-z_][a-z0-9_]*$`.
- A `_begin` event is closed by the same stem with `_end_ok` or `_end_error`:

```
[c9k2vf3p][mp4gif_worker_begin]
[c9k2vf3p][mp4gif_worker_end_ok] 4.512s

[c7t0xb1m][mp4gif_worker_begin]
[c7t0xb1m][mp4gif_worker_end_error] 0.884s ffmpeg exit=1
```

- Use `_end` when the logged outcome, such as an HTTP status, already says what
  happened and classifying it as ok or error would be misleading.

### details

- Human-readable and terse.
- Never contain a physical newline.
- Never contain secrets, tokens, signed URLs, URL query values, bodies, or
  headers.
- Prefer references to payloads over copying payloads into the log.

Values are encoded as follows:

- A printable ASCII word without spaces, double quotes, backslashes, or square
  brackets is written bare. A bare value is exactly the bytes that were sent:
  it cannot span words, break the line, or mint a fake `[tag]`.
- Other strings are JSON-quoted, so newlines and control characters are
  escaped, and an empty value stays visible as `""`.
- Arrays, objects, booleans, and null use compact JSON.
- An unordered list is sorted and prefixed with its count, for example
  `3:[180,783,846]`, `2:["bar","foo"]`, or `0:[]`. Do not sort ordered values.
- Truncation preserves valid UTF-8 and ends with the number of omitted bytes,
  for example `...+4821`.

## Limits

Try to keep one log line under 2k UTF-8 bytes.

A log line describes an event; it is not payload storage.

## group_exit

An implementation may close a group:

```
[group_uid][group_exit]
```

It is optional, and it mainly serves to detect leaks. After `group_exit` is
emitted, no producer should emit another event for that group. A parent may
emit `group_exit` for work it abandons, such as a child that timed out.

"After" means producer emission order, not timestamp or collector ingestion
order. Buffering may deliver an older event after `group_exit`; that alone is
not an error. Reliable detection across processes needs preserved per-group
order, a shared sequence, or another causal-order signal. Without one,
cross-process detection is advisory.

Consumers must accept groups without `group_exit`; its absence makes no claim.
