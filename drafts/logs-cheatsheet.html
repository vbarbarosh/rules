Logs

Legend

[time]
ISO-8601 UTC with milliseconds; dropped when a collector adds it
group_uid
one unit of work — request, job, cron run
[sender]
one call site, unique in the whole codebase
group_spawn
opens a group; parent= names the caller's group
group_exit
optional close; after it, no producer emits for that group
_begin
operation start
_end_ok
completed successfully
_end_error
completed with an error
spawn relation — happened inside the parent group

Rules

  • A line carries time, group_uid, sender, details — nothing else. Elapsed time, status, and every other measurement belong in details.
  • time is required when writing to a file, and omitted when the runtime already timestamps the line, as docker does.
  • Every event belongs to a group: one request, job, or cron run. The uid is opaque, usually a cuid.
  • A group opens with group_spawn, emitted synchronously before the uid is passed anywhere:
    • [new_group_uid][group_spawn] parent=old_group_uid
    • Omit parent= for a root group. A receiver uses the caller's uid as the parent of its new group.
  • sender identifies one logging call site. The name is unique in the whole codebase, so a grep lands on one place. It is snake_case and matches ^[a-z_][a-z0-9_]*$.
  • A _begin event is closed by the same stem:
    • _end_ok — completed successfully
    • _end_error — completed with an error
    • _end — the outcome itself, such as an HTTP status, already says what happened
  • group_exit is optional and mainly detects leaks. Its absence makes no claim, and consumers must accept groups without it.

Limits

  • Try to keep one line under 2k UTF-8 bytes.
  • A log line describes an event; it is not payload storage.
  • details never contains a physical newline.

Never in a line

  • secrets and tokens
  • signed URLs and URL query values
  • request or response bodies, headers

Log a reference to the payload instead of the payload.

Details: value encoding

bare      name=select_users    exit=1    ETIMEDOUT    4.512s
quoted    "no space left on device"    "line one\n"    ""
json      {"beta":true}    [1,2,3]    null
counted   3:[180,783,846]    2:["bar","foo"]    0:[]
truncated {"name":"asparagus","qua...+4821
  • bare — a printable ASCII word without spaces, double quotes, backslashes, or square brackets. A bare value is exactly the bytes that were sent: it cannot span words, break the line, or mint a fake [tag].
  • quoted — every other string is JSON-quoted, so newlines and control characters are escaped, and an empty value stays visible as "".
  • json — arrays, objects, booleans, and null use compact JSON.
  • counted — an unordered list is sorted and prefixed with its count. Ordered values are never sorted.
  • truncated — truncation preserves valid UTF-8 and ends with the number of omitted bytes.

After group_exit

  • "After" means producer emission order — not timestamp, not collector ingestion order.
  • Buffering may deliver an older event later; that alone is not an error.
  • A parent may emit group_exit for work it abandons, such as a child that timed out.
  • Cross-process detection needs preserved per-group order, a shared sequence, or another causal-order signal. Without one it is advisory.
