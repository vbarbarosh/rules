# Project audit — 2026-11-09

Repository: `vbarbarosh/rules`, branch `main`, HEAD `63173ed8a15a4a320f62c8840c0c38d554d056e3` (v0.1.20); 1141 tracked files, 348 commits; first commit 2025-04-09, latest commit 2026-11-09. Nothing was changed: every finding below is open.

## Scope

Asked: a full audit of the project. It was run from scratch: no reader was given an earlier finding, except the one whose task was to recheck them.

Checks performed:

- Eleven readers, each on one side, each reading its files whole: the index against its sources (rows CORE to FILE; rows PROJ to LINT with the animations and system pages); rule against rule (the code rules; all the others); the linter (`src/`, `bin/lint`, LINTING.md), run on samples; the repository's own code (`bin/`, `src/`, `docs/search.js`, `demos/`) against the code rules; the tests and the checks; the pages as source (templates, built pages, the hand-written pages) against the CSS, UI, UIM and animation rules; the pages in a browser; the guides, glossaries, diagrams and APIs; the project's layout, front documents and package.
- A twelfth reader rechecked, item by item, the 74 contradictions listed on 2026-10-28 and the 13 findings the note of 2026-10-08 left open.
- Every finding was read again at its line by the auditor; the quoted lines of the reports were compared with the files by a script (four misses in the recheck's 156 quotes, all of them line wraps or bold marks). One reported finding was dropped as wrong: the operator fix that writes `/a//2` leaves a division, not a comment.
- Reproduced by hand: the rule card that shows raw Markdown; the lint configuration of the three bin scripts (`eslint --print-config`) and the five errors of `bin/build-search`; the 90 mangled entities of `docs/search.json`; the configure example under strict mode; seven canonical forms through `bin/lint`; fourteen linter samples (an unparsable stylesheet, a tight `=`, a `<!--` inside a script, a template literal in a page script, `'use strict'`, an object getter, code after a closing brace, `data-src`, a plain-CSS Vue block, a jQuery error handler, a Promise executor, a named require above a default import, a folder named vendor).
- `npm run check` in a scratch clone: exit 0. That is the lint, 343 of 343 unit tests, `bin/build` with the 14 built files unchanged, and `bin/self-check`.
- The browser tests, one file per run: 10 of 11 files pass (1,525 tests). `tests/browser/try-it.test.js` was run 22 times in all: 4 of the 14 runs made while other work loaded the machine failed, 8 of 8 on the idle machine passed.
- Every link of the 133 Markdown files: 1,367 found, 1,362 resolve to a tracked file and an existing anchor; the other 5 are example text inside canonical forms.
- Every tracked picture (921): each is named by some file; each has its dark twin except the two theme icons and one screenshot.
- The index's header against its rows: 285 rules, 18 groups, 56 sources, every code unique, the retired codes unused.
- The commit titles and bodies of all 348 commits against GIT-01 to GIT-05, counted apart for the 209 since the rule was written.
- The tracked files and the history for addresses, home paths, host names, keys and tokens.
- `npm audit`, `npm outdated`, `npm pack --dry-run` (28 files), the declared dependencies against the `require` calls.
- File modes, line endings, tabs and trailing spaces of every tracked text file.

Not exercised: Firefox, WebKit and real phones (Chromium only); print styles and screen readers; the published site and every external link (nothing outside was fetched but the package registry); the quick start `npx vbarbarosh/rules src` over the network and an install into another project (the packed files were run in place instead); `bin/configure` and `bin/test`; any release, tag or publish command; ESLint 9.39 (only 10.11.0 is installed); the PHP examples; the 28 findings the note of 2026-10-08 marks fixed; the eight quiz questions of 2026-10-13. The pictures were checked by `tests/browser/pictures.test.js` (1,326 checks) and a few by eye, not one by one.

## Verdict

The project is in working order and its machinery holds: the build is reproducible, every unit test passes, every link and picture resolves, the index counts what it says. The main risk is not there. It is that the rulebook contradicts itself in the open and nothing catches it: 48 contradictions between rules are open; of the 74 listed on 2026-10-28, 68 still stand, four were already settled by approval entries and two are withdrawn; six examples the index marks as right are wrong by other rules, four of them rejected by the repository's own linter. Beside that stand the defects a visitor or a user meets today: between 721 and 1066 px wide the header of the seven docs pages runs off the right edge (three more pages do it in narrower ranges); on a phone the search box shrinks to 26 px once the page is scrolled; one rule card prints raw Markdown where its picture should be; the search data holds 90 mangled entities; the lint run gives the three bin scripts no rules at all; a stylesheet that cannot be parsed passes the linter. The eleven browser test files and the scroll test are run by no script, and one of them fails when the machine is busy: 4 of 14 such runs here.

200 findings: 7 high, 54 medium, 139 low. 105 are slips with a clear fix, 26 are bugs, 69 are choices only the author can make. Almost all are small: 175 of 200 need a small fix.
