# Instructions for agents

What is expected of an agent: how it does the work, without the author having
to say it each time. Handed to an agent as it is, "work like this". Kept apart
from the rules, which say how the code looks.

- [consequences_first.md](consequences_first.md) — before the first edit, picture what the change leads to, "what if this, what if that"; the entries below follow from it
- [one_example_all_cases.md](one_example_all_cases.md) — one example stands for all cases like it: find them, change them all, say the consequences first
- [every_state_before_done.md](every_state_before_done.md) — a UI is tried in every state (long, empty, one letter, absurd) before it is called done; its layout holds them all; the reply says what was decided and asks what is ambiguous
- [every_point_of_view.md](every_point_of_view.md) — one task is several stories: the user's, the implementation's, the attacker's (and the operator's, the next developer's, the newcomer's); tell each before done; the screen follows the user's story
