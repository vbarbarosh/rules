JavaScript formatting / applied

Make code predictable.

Formatting is not decoration. It gives every kind of code a known address, makes names carry shape, and lets control flow read from top to bottom.

01A file has an address system.

Before reading a line, you should already know where dependencies, policy, behavior, helpers, and execution live.

01 / BIN
#!/usr/bin/env node
02 / DEPS
const cli = require('@vbarbarosh/node-helpers/src/cli');
const fs = require('node:fs');
03 / POLICY
const report_limit = 31;
04 / RUN
cli(main);
05 / ENTRY
function main()
{
    // public behavior
}
06 / HELP
function format_percent(value)
{
    return `${value}%`;
}
Dependencies are visible.

require statements sit together and sort cleanly.

Execution is announced early.

After dependencies and policy, cli(main); says: start here.

main owns orchestration.

It is the first declaration and the one exception to domain-first naming.

Helpers explain downward.

Each name encountered above can be resolved by continuing to read.

02Brace position reveals scope.

The unusual part is intentional: module-level declarations form landmarks; nested behavior stays visually compact.

Module scope brace moves down
function main()
{
    // top-level landmark
}

The brace creates a strong horizontal break before the file’s primary behavior.

Nested scope brace stays put
function main()
{
    function limit_print(limit) {
        console.log(limit);
    }
}

Nested declarations, callbacks, and control flow keep the brace on the declaration line.

A function is a verb phrase. Data is a noun phrase. The assignment reads like a small, testable sentence.

04Watch the rules change the code.

The result is longer by line count and shorter by interpretation time. Shape, mutation, and exit are all exposed.

Before compressed decisions
const group = (arr) =>
    arr.reduce((acc, x) => {
        (acc[x.role] ||= []).push(x);
        return acc;
    }, {});

const result = group(users);

module.exports = group;
Applied each decision gets a line
function users_group_by_role(users)
{
    const out = {};
    for (const user of users) {
        out[user.role] ??= [];
        out[user.role].push(user);
    }
    return out;
}

module.exports = users_group_by_role;

07The 30-second review. scan top → bottom

1
Can I identify the file type?

A library ends with one export. A script hands main to cli(main); after globals.

2
Is the entry convention correct?

A script declares main first; a library uses a domain-first function name.

3
Do names reveal data shape?

Plurality, _by_, and _sorted_by_ agree with the value.

4
Does control flow read downward?

Guards return early; loops are explicit; deep pipelines are gone.

5
Is the constructed result named out?

The caller gives it the domain name after the function returns.

6
Are boundaries explicit?

Dependencies, object fields, helpers, and execution are visible.
